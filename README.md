# Hibernate Deep Dive
> Проект-исследование преимуществ ORM над классическим JDBC

---

## 🎯 Цель проекта
Демонстрация перехода от низкоуровневой работы с БД (JDBC) к современной объектно-реляционной модели. Проект наглядно показывает, как Hibernate решает проблемы дублирования кода и ручного управления ресурсами.

---

## ⚔️ Сравнение: JDBC vs Hibernate

| Возможность | JDBC (Old School) | Hibernate (Modern) |
| :--- | :--- | :--- |
| **Код** | Многословный (Boilerplate) | Лаконичный (Declarative) |
| **Типы данных** | Ручной маппинг ResultSet | Автоматический через `@Entity` |
| **Транзакции** | Ручное управление `commit/rollback` | Декларативное управление |
| **Связи** | Тяжелые JOIN-запросы вручную | Удобные аннотации `@ManyToOne` |

---

## 🏗 Архитектура сущностей

Проект включает в себя сложные примеры маппинга, выходящие за рамки простых таблиц:

### 🔹 Компоненты (`@Embedded`)
Данные пользователя сгруппированы в `PersonalInfo` (Firstname, Lastname, BirthDate), что позволяет соблюдать принципы **DRY** и **Encapsulation**.

### 🔹 Ассоциации
* **User ↔ Company**: Связь "Многие-к-одному".
* **Lazy Loading**: Использование прокси-объектов (**ByteBuddy**) для оптимизации памяти.

### 🔹 Продвинутые типы
* **JSONB**: Хранение неструктурированной информации в PostgreSQL.
* **Enums**: Маппинг ролей через `EnumType.STRING`.

---

## 🛠 Технологический стек

* **Core**: Hibernate Framework
* **DB**: PostgreSQL (с поддержкой схем и типов JSONB)
* **Optimization**: ByteBuddy (Proxy generation)
* **Utils**: Lombok, Hypersistence-utils
